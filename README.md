# monah

Локальное музыкальное веб-приложение для прослушивания музыки — в тёмно-серых тонах. Музыку в
библиотеку добавляют сами слушатели: загрузил файл — трек сразу виден всем.

![monah](https://img.shields.io/badge/next.js-15-black) ![react](https://img.shields.io/badge/react-19-black) ![sqlite](https://img.shields.io/badge/sqlite-node%3Asqlite-black)

## Что внутри

- **Плеер**: play/pause, seek, громкость, очередь, shuffle, повтор (все / один), «продолжить с места»,
  горячие клавиши. На Android — Media Session (кнопки на наушниках и блокировочный экран) и Wake
  Lock, чтобы экран не гас во время воспроизведения.
- **PWA**: устанавливается на домашний экран Android и iOS, работает в полноэкранном режиме,
  service worker кэширует статику и изображения плейлистов/профилей (аудио и данные пользователя не
  кэшируются).
- **Мобильный интерфейс**: нижняя навигация с крупными touch-целями, безопасные отступы под вырез
  экрана, перемотка касанием по верхней полоске плеера.
- **Загрузка музыки**: drag & drop, несколько файлов, ZIP-архивы, прогресс по каждому, теги из файла
  (если тегов нет — исполнитель и название разбираются из имени файла вида «Артист - Название»),
  лимит 50 МБ на трек.
- **Стриминг с `Range`**: перемотка работает мгновенно даже на больших файлах.
- **Серия прослушиваний**: огонёк с числом дней рядом с ником; минута музыки в день продлевает
  серию, на 10/30/50/100 днях и дальше каждые 50 — праздничная вспышка.
  В профиле рядом с загрузками видно суммарное время в музыке.
- **Аккаунты**: регистрация, вход по e-mail или имени пользователя, сессии в httpOnly-cookie.
- **Инвайты и админка**: загрузка по коду приглашения, управление правами, жалобы и модерация.
- **Плейлисты**: создание, удаление, добавление/удаление треков, перетаскивание порядка мышью,
  собственные аватар и обложка.
- **Профили**: аватар, обложка, имя и описание; редактируются на своей странице профиля.
- **Импорт плейлистов**: по ссылке Deezer, файлом плейлиста (M3U/M3U8/JSON/CSV) или списком
  строк — совпадения ищутся в библиотеке, недостающие треки сохраняются как «не загружено».
- **Лайки и история**: «Мне нравится», «Недавно слушали», счётчики прослушиваний.
- **Страницы**: главная, поиск (треки / исполнители / плейлисты / жанры), медиатека, трек,
  исполнитель, плейлист, профиль.
- **Демо-каталог**: 10 треков, полностью синтезированных кодом (23 минуты музыки), 7 исполнителей,
  3 плейлиста с обложками и история прослушиваний.

## Изображения

У треков нет обложек: в списках, карточках и плеере показывается чёрный квадрат с белым названием
трека. Картинки есть только у плейлистов и пользователей — по два изображения:

| | Аватар | Обложка |
|---|---|---|
| Плейлист | квадрат в сайдбаре, карточках и меню | широкий баннер на странице плейлиста |
| Пользователь | круг в шапке и профиле | баннер на странице профиля |

Загружаются на странице плейлиста («Изменить плейлист») и в профиле («Редактировать профиль»).
Браузер уменьшает картинку до 1600 px (обложка) или 512 px (аватар) и отправляет WebP, сервер
дополнительно проверяет формат по сигнатуре файла. Старые обложки треков удаляются скриптом:

```bash
npm run cleanup:covers -- --dry-run   # посмотреть, что будет удалено
npm run cleanup:covers                # удалить файлы и обнулить tracks.cover
```

Файлы, оставшиеся после отменённой загрузки картинки, приложение подчищает само раз в час.
Вручную: `npm run cleanup:images -- --dry-run`, затем без флага.

## Серия прослушиваний

Огонёк рядом с ником показывает, сколько дней подряд слушатель набирает минуту музыки.
День закрывается при 60 секундах воспроизведения; плеер считает реальное продвижение
(перемотка не в зачёт) и раз в ~20 секунд отправляет порцию в `/api/listen`. Секунды
хранятся в таблице `listening_days`, серия считается на лету — фоновых задач нет.

- Серия видна всем рядом с ником: в профиле, у владельца плейлиста и у загрузившего трек.
  Чужим показывается только длина серии, прогресс дня видит лишь владелец.
- Уровни огня: 1–9, 10–29, 30–49, 50–99 и 100+; на 10, 30, 50, 100 днях и каждые
  следующие 50 показывается поздравление.
- Часовой пояс — браузерный: клиент присылает свою дату, сервер принимает её только
  в пределах ±1 дня от UTC.
- У аккаунта без единого закрытого дня чип не показывается, чтобы не рябить нулями.

## Приложение для Android

Сайт упакован в Trusted Web Activity: APK открывает https://monah2.duckdns.org в полноэкранном
Chrome без адресной строки, с общей сессией, фоновой музыкой и управлением с экрана блокировки.

- Сборка живёт вне репозитория (`C:\Users\Stasg\monah-twa`): `twa-manifest.json`, ключ подписи
  `monah-release.keystore` и сгенерированный Gradle-проект. **Ключ нельзя терять** — без него
  обновления не встанут поверх установленного приложения.
- В репозитории лежат только `public/.well-known/assetlinks.json` (цифровой отпечаток ключа
  для проверки домена) и страница `/download`.
- Готовый APK кладётся на сервер в `storage/app/monah.apk`, рядом `storage/app/build.json`
  с версией. Страница `/download` и `/api/app/android` читают их напрямую.
- Обновления только вручную: поднять `versionCode` и `appVersion` в `twa-manifest.json`,
  пересобрать, заменить файл на сервере.

```powershell
# в C:\Users\Stasg\monah-twa
$env:BUBBLEWRAP_KEYSTORE_PASSWORD = Get-Content .\keystore-password.txt -Raw
$env:BUBBLEWRAP_KEY_PASSWORD = $env:BUBBLEWRAP_KEYSTORE_PASSWORD
npx @bubblewrap/cli build
```

## Запуск

```bash
npm install
npm run seed     # один раз: генерирует демо-библиотеку (~2 минуты)
npm run dev
```

Откройте http://localhost:3000

Или просто дважды кликните `start.bat` — он сам поставит зависимости, соберёт демо-каталог и запустит
сервер.

**Демо-аккаунт (для локального запуска):** `demo@monah.local` / `monah123`
У демо-аккаунта есть плейлисты, лайки и история. Пароль у аккаунтов исполнителей тот же.
На сервере демо-аккаунт администратором не является — права даёт только `ADMIN_EMAIL`.

Пересоздать демо-каталог с нуля:

```bash
npm run seed -- --force
```

## Импорт плейлиста

Поддерживаются три способа:

1. **По ссылке Deezer**: `https://www.deezer.com/playlist/...` или короткая `link.deezer.com`.
   Сервер забирает метаданные (названия и исполнителей) и обложку.
2. **Файл плейлиста**: CSV, M3U, M3U8, JSON или TXT. Экспортируйте плейлист из своего плеера и
   загрузите файл.
3. **Список строк** вида `Название — Исполнитель`.

Импорт сопоставляет треки с библиотекой по названию и исполнителю, создаёт плейлист в исходном
порядке и сохраняет ненайденные треки как «не загружено». После загрузки файлов откройте плейлист и
нажмите «Проверить снова» — они добавятся автоматически.

Аудио из сервисов не скачивается — только список; файлы должны быть вашими или свободными.

## Технологии

| Слой | Что используется |
| --- | --- |
| Фронтенд | Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS 4 |
| Иконки | lucide-react |
| Бэкенд | Route Handlers Next.js (Node runtime) |
| База | SQLite через встроенный `node:sqlite` (без нативных зависимостей) |
| Аудио | `music-metadata` для тегов и обложек, `@breezystack/lamejs` для генерации демо-MP3 |
| Авторизация | `bcryptjs` + JWT-сессия (`jose`) в httpOnly-cookie |

Никаких внешних сервисов, облачных БД и обязательного Docker — локально всё работает как есть. Для
публикации в комплекте есть `Dockerfile`, `docker-compose.yml` и `Caddyfile`.

## Деплой на Oracle Always Free

Бесплатный ARM-сервер (4 CPU, 24 ГБ RAM, 200 ГБ диска, 10 ТБ трафика). Сайт работает на своём
SQLite и локальном диске, поэтому переезд на serverless не нужен.

### 1. Сервер

1. Создайте аккаунт Oracle Cloud и инстанс **Ampere A1** (Ubuntu 24.04, 4 OCPU / 24 ГБ / 200 ГБ).
   Карта нужна только для верификации, списаний на Always Free нет.
2. В Security List откройте входящие TCP 22, 80, 443 (и UDP 443 для HTTP/3).
3. На сервере:

```bash
sudo apt update
sudo apt install -y git docker.io docker-compose-v2 ufw
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"   # затем перелогиньтесь
sudo ufw allow OpenSSH && sudo ufw allow 80,443/tcp && sudo ufw allow 443/udp && sudo ufw enable
```

### 2. Домен

Бесплатный поддомен через DuckDNS:

1. Создайте `monah.duckdns.org` и направьте на публичный IP сервера.
2. HTTPS Caddy выпустит сам при первом запросе, домен указывается в `.env`.

### 3. Конфигурация

```bash
git clone <ваш-репозиторий> monah && cd monah
cp .env.production.example .env.production
nano .env.production          # AUTH_SECRET, SITE_URL, ADMIN_EMAIL, CONTACT_EMAIL

openssl rand -hex 32          # вставьте результат в AUTH_SECRET
echo "DOMAIN=monah.duckdns.org" > .env
```

`DOMAIN` читает Docker Compose, остальные переменные — приложение.

### 4. Данные

```bash
mkdir -p storage
sudo chown -R 1001:1001 storage
```

Вариант «с нуля»: ничего не кладите в `storage` — при первом запуске создастся пустая база, а первый
зарегистрированный пользователь (или аккаунт с `ADMIN_EMAIL`) станет администратором. Создайте
админский аккаунт **до** того, как поделитесь ссылкой.

Вариант «с демо-каталогом»: перенесите локальную папку `storage` (SQLite + mp3 + обложки):

```bash
# на локальной машине
scp -r storage ubuntu@<ip>:/home/ubuntu/monah/
# на сервере
sudo chown -R 1001:1001 storage
```

**Важно про демо-аккаунт.** Локальный `demo@monah.local / monah123` не является администратором
на сервере: права даёт только `ADMIN_EMAIL`. После первого запуска:

1. Зарегистрируйте аккаунт с e-mail из `ADMIN_EMAIL` — он станет администратором при входе.
2. Откройте `/admin` → «Пользователи» и заблокируйте `demo` (или смените ему пароль), потому что
   этот пароль известен всем.

### 5. Запуск

```bash
docker compose up -d --build
docker compose ps
curl -fsS https://monah.duckdns.org/api/health
```

Первый запуск собирает образ (~2–3 минуты на ARM). Caddy получит сертификат и начнёт проксировать
запросы на приложение.

### 6. Эксплуатация

```bash
./deploy.sh                    # git pull + пересборка + health-check
./scripts/backup.sh            # бэкап БД и файлов в backups/ (хранится 7 дней)
```

Ежедневный бэкап в 04:00:

```cron
0 4 * * * cd /home/ubuntu/monah && ./scripts/backup.sh >> backups/backup.log 2>&1
```

Мониторинг: `/api/health` отдаёт состояние БД и свободного места (503, если места критически мало).
Подключите бесплатный UptimeRobot/BetterStack на этот адрес.

Дополнительно можно копировать `backups/` в Backblaze B2 (10 ГБ бесплатно) через `rclone`.

### 7. Права и модерация

- Загрузка закрыта по умолчанию: на `/upload` пользователь вводит инвайт-код.
- Коды создаются в `/admin` (пункт меню «Админка» у администратора). Код можно сделать
  многоразовым и ограничить сроком.
- Там же: выдача прав, блокировка, удаление треков, жалобы и статистика диска.
- Лимиты на пользователя задаются в `.env.production`:
  `UPLOAD_LIMIT_TRACKS` (по умолчанию 100), `UPLOAD_LIMIT_BYTES` (2 ГБ),
  `MIN_FREE_BYTES` (1 ГБ — порог остановки загрузок).
- Жалобы доступны из меню «…» у трека; правила и политика — `/rules` и `/privacy`.
  Контакт для жалоб на копирайт задаётся через `CONTACT_EMAIL`.

### 8. Обновления и откат

`./deploy.sh` делает `git pull --ff-only`, пересобирает только контейнер приложения и перезапускает
его без простоя Caddy. Если что-то пошло не так: `git checkout <предыдущий-коммит> && ./deploy.sh`.
База и файлы лежат в `storage/` и не затрагиваются пересборкой.

## Структура

```
src/
  app/
    (main)/            # приложение с сайдбаром и плеером
      page.tsx         # главная
      search/          # поиск и жанры
      library/         # медиатека: плейлисты, лайки, загрузки
      import/          # импорт плейлиста из CSV или списка
      upload/          # загрузка треков + активация инвайта
      admin/           # админка: инвайты, права, жалобы, треки
      rules/ privacy/  # правила и политика
      track/[id]/      # страница трека
      artist/[name]/   # страница исполнителя
      playlist/[id]/   # плейлист
      profile/[username]/
    (auth)/            # вход и регистрация
    api/               # auth, upload, stream, covers, tracks, likes, plays, playlists,
                       # invites, reports, health
  components/          # плеер, треклисты, карточки, меню, формы
  lib/                 # БД, запросы, авторизация, квоты, rate limit, форматирование
scripts/
  synth.mjs            # синтезатор: осцилляторы, фильтры, барабаны, реверб
  png.mjs              # генератор обложек (PNG без зависимостей)
  songs.mjs            # описание 10 демо-треков
  seed.mjs             # рендер MP3 + наполнение базы
  backup.sh            # бэкап SQLite и файлов
  fix-track-tags.mjs   # починка исполнителя/названия по тегам файлов (--dry-run)
docker-compose.yml     # app + Caddy
Caddyfile              # HTTPS, сжатие, лимит тела, security-заголовки
deploy.sh              # обновление на сервере
storage/               # база и файлы (создаётся автоматически, в git не попадает)
```

## Горячие клавиши

| Клавиша | Действие |
| --- | --- |
| `Space` | play / pause |
| `→` / `←` | ±5 секунд |

## Ограничения

- Загрузка: mp3, m4a, aac, ogg, opus, flac, wav — до **50 МБ на трек** и до **250 МБ за один заход**.
  Можно загрузить ZIP-архив с треками: он распаковывается в браузере (`fflate`) и каждый аудиофайл
  проходит обычную проверку. Тип проверяется по магическим байтам, аудио дополнительно парсится
  `music-metadata`. Поля формы заполняются в порядке: теги файла → разбор имени файла
  («Артист - Название») → имя загрузившего. Всё можно поправить вручную перед публикацией.
- Нет транскодинга: mp3/m4a/wav играют везде, flac/ogg/opus — в Chrome, Firefox и Edge (Safari может
  не проиграть).
- База и файлы лежат локально в `storage/` — на сервере это постоянный том, локально папка
  проекта. Для переноса достаточно скопировать `storage/`.
- Загрузка по инвайтам и лимиты на пользователя защищают бесплатный сервер от переполнения, но
  публичный сайт всё равно требует модерации: жалобы, удаление треков и контакт для правообладателей.

## Безопасность

- Пароли — bcrypt, сессии — подписанный JWT в httpOnly/SameSite=Lax cookie, `secure` в production.
  Смена пароля и «выйти на всех устройствах» увеличивают `session_version` и завершают старые сессии.
- Rate limit: логин 10/мин с IP, регистрация 5/час, загрузка 20/час на пользователя, жалобы и
  инвайты 10/час, прослушивания 120/мин. `X-Forwarded-For` перезаписывается Caddy.
- Проверка файлов: расширение + MIME + магические байты + разбор `music-metadata`.
- Security-заголовки на уровне приложения и Caddy, CSP, HSTS, лимит тела запроса 60 МБ.
- Заблокированный пользователь не может войти и не получает сессию.
- Админка и API закрыты проверкой роли; `/admin` не индексируется.

## Лицензии и правовое

Проект — учебная реализация интерфейсных паттернов музыкальных стримингов со своей айдентикой:
название «monah», свой логотип и палитра. Логотипы, шрифты и ассеты сторонних сервисов не
используются.

Все демо-треки сгенерированы математически этим проектом, чужих записей в репозитории нет.
Ответственность за музыку, которую загружают пользователи, лежит на них.
